## Directory Purposes

**`backend/agents/`:**
- Purpose: LangGraph agent implementations (one file per agent)
- Contains: Python functions conforming to `(AlertState) -> AlertState` signature
- Key files:
  - `orchestrator.py` — Pipeline entry, input validation
  - `data_fetcher.py` — Synthetic data generator (fallback)
  - `data_fetcher_real.py` — Real parquet/Athena/GAM data loader (primary)
  - `data_validator.py` — Schema validation, A0 gap detection, delta computation
  - `anomaly_detector.py` — Z-score + threshold + consecutive-hours checks
  - `triage_classifier.py` — TRAFFIC_DRIVEN/COVERAGE_DRIVEN/MIXED/REVENUE_ONLY
  - `contributor_analyzer.py` — Per-publisher contribution analysis
  - `geo_analyzer.py` — Per-geo-cluster breakdown
  - `environment_splitter.py` — WEB/AMP/APP split + AMP drift detection
  - `insight_generator.py` — Cross-dimensional insights + template fallback
  - `report_builder.py` — Alert ID generation, JSON payload, markdown report
  - `notifier.py` — DB save + Slack/email delivery

**`backend/api/`:**
- Purpose: FastAPI REST API surface
- Contains: Route handlers, Pydantic schemas, auth middleware, rate limiting
- Key files:
  - `routes.py` — Core alert CRUD, backtest, metrics, health (prefix: `/api`)
  - `publisher_routes.py` — Publisher analytics endpoints (prefix: `/api/publishers`)
  - `admin_routes.py` — Data source + alerting rules config (prefix: `/api/admin`)
  - `auth.py` — Google OAuth login/callback/me/logout (prefix: `/auth`)
  - `schemas.py` — All Pydantic request/response models
  - `rate_limit.py` — slowapi limiter instance

**`backend/workflow/`:**
- Purpose: LangGraph graph definition and state type
- Contains: Graph builder, conditional edge functions, pipeline runner
- Key files:
  - `graph.py` — `build_graph()`, `compile_graph()`, `run_pipeline()`, conditional edge functions
  - `state.py` — `AlertState` TypedDict definition

**`backend/db/`:**
- Purpose: SQLite database schema, connection management, CRUD operations
- Key files:
  - `database.py` — Connection pool (thread-local), `init_db()`, migrations, `get_db()` context manager
  - `models.py` — Pydantic models, enums, SQL CREATE statements, `generate_alert_id()`
  - `operations.py` — All CRUD: `create_alert()`, `get_alerts()`, `get_alert_by_id()`, `update_alert_status()`, etc.

**`backend/connectors/`:**
- Purpose: External data source integrations
- Key files:
  - `athena.py` — AWS Athena query with parameterized SQL, retry, timeout
  - `gam.py` — Google Ad Manager reporting API with CSV parsing

**`backend/prompts/`:**
- Purpose: LLM prompt template files (loaded at runtime by agents)
- Contains: `.txt` files with `{placeholder}` format strings

**`backend/scheduler/`:**
- Purpose: Periodic job scheduling
- Key files:
  - `scheduler.py` — 3 jobs (A1+A3 every 2h, A2 every 6h, recheck every 5min)

**`backend/utils/`:**
- Purpose: Shared utilities
- Key files:
  - `config_loader.py` — Thread-safe YAML config singleton with Pydantic validation
  - `logger.py` — Structured logging setup
  - `llm_retry.py` — Anthropic SDK wrapper with exponential backoff (3 retries)

**`backend/backtest/`:**
- Purpose: Historical alert simulation
- Key files:
  - `runner.py` — Backtest coordinator (tries real runner, falls back to synthetic)
  - `runner_real.py` — Real-data backtest using parquet + full pipeline

**`config/`:**
- Purpose: Application configuration
- Key files:
  - `alerting_rules.yaml` — All thresholds, severity levels, geo clusters, top publishers list, scheduling params

**`data/baseline/`:**
- Purpose: Pre-aggregated parquet data files (source of truth)
- Contains: 3 parquet files (~1.75M total rows)
- Generated: External ETL (not in this repo)
- Committed: Yes (tracked in git)

**`data/seasonal/`:**
- Purpose: Pre-computed seasonal analysis and recurring pattern data
- Contains: JSON files produced by analysis scripts
- Key files:
  - `ecpm-seasonal-analysis.json` — 15 seasonal periods + week mapping
  - `enriched-recurring-patterns.json` — Per-publisher eCPM/hidden/danger patterns
  - `optimization-windows-enriched.json` — Driver-labeled optimization windows

**`frontend/src/api/`:**
- Purpose: Centralized API client layer
- Key files:
  - `client.ts` — `fetchJSON()` wrapper, all TanStack Query hooks (25+ hooks), type imports

**`frontend/src/pages/`:**
- Purpose: Page-level route components (one per route or route group)
- Key files:
  - `DashboardPage.tsx`, `AlertsListPage.tsx`, `AlertDetailPage.tsx`
  - `PublishersPage.tsx`, `PublisherDetailPage.tsx`
  - `BacktestPage.tsx`, `HealthPage.tsx`, `AdminPage.tsx`, `DocsPage.tsx`

**`frontend/src/components/`:**
- Purpose: Reusable UI components organized by domain
- Key subdirectories:
  - `alerts/` — 7 section components for alert detail page
  - `charts/` — 3 Recharts wrappers (RevenueTrend, GeoPie, EnvironmentBar)
  - `dashboard/` — Dashboard-specific widgets (Stats, Filter, Table, RevenueStatus24h)
  - `layout/` — App shell: `AppLayout.tsx` (Outlet), `Header.tsx`, `Sidebar.tsx`, `PageContainer.tsx`
  - `ui/` — 8 reusable primitives (Badge, Button, Card, MetricCard, Skeleton, AlertBox, DeltaIndicator, DataTable)

**`frontend/src/types/`:**
- Purpose: Shared TypeScript type definitions
- Key files:
  - `alert.ts` — All alert-related types (Alert, AlertSummary, Contributor, etc.)
  - `publisher.ts` — Publisher-related types (PublisherSummary, EcpmAnalysis, etc.)

**`scripts/`:**
- Purpose: Maintenance and data generation scripts
- Key files:
  - `regenerate_alerts.py` — Generate alerts in DB from real parquet data

**Testing:**
- No test files detected in the codebase.

## Naming Conventions

**Files (Backend):**
- Snake_case for all Python modules: `data_fetcher_real.py`, `config_loader.py`
- Agent files match agent names: `orchestrator.py`, `triage_classifier.py`

**Files (Frontend):**
- PascalCase for React components: `AlertDetailPage.tsx`, `DashboardStats.tsx`
- camelCase for utility/hook files: `client.ts`, `useAlertFilters.ts`
- PascalCase for type files with lowercase extension: `alert.ts`, `publisher.ts`

**Directories:**
- Lowercase with underscores (backend): `backend/agents/`, `backend/db/`
- Lowercase (frontend): `frontend/src/components/alerts/`

## Where to Add New Code

**New Agent:**
- Implementation: `backend/agents/{agent_name}.py`
- Register in graph: `backend/workflow/graph.py` (add node + edges)
- Add state keys if needed: `backend/workflow/state.py`

**New API Endpoint:**
- Alert/core endpoints: `backend/api/routes.py`
- Publisher endpoints: `backend/api/publisher_routes.py`
- Admin endpoints: `backend/api/admin_routes.py`
- New domain: Create new router file in `backend/api/`, mount in `backend/main.py`
- Add schema: `backend/api/schemas.py`

**New Frontend Page:**
- Page component: `frontend/src/pages/{PageName}Page.tsx`
- Register route: `frontend/src/App.tsx`
- Add API hook: `frontend/src/api/client.ts`
- Add types: `frontend/src/types/{domain}.ts`

**New Frontend Component:**
- Alert detail section: `frontend/src/components/alerts/`
- Chart: `frontend/src/components/charts/`
- Dashboard widget: `frontend/src/components/dashboard/`
- Reusable UI: `frontend/src/components/ui/`

**New Data Connector:**
- Implementation: `backend/connectors/{connector_name}.py`
- Integration: `backend/agents/data_fetcher_real.py` (add to fallback chain)
- Admin config: `backend/api/admin_routes.py` (add test endpoint)

**New Config Section:**
- YAML: `config/alerting_rules.yaml`
- Pydantic model: `backend/utils/config_loader.py`

**Utilities:**
- Shared backend helpers: `backend/utils/`
- Shared frontend helpers: `frontend/src/lib/`

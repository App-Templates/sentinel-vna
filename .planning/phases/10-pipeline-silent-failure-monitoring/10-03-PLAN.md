<alternatives_considered>
**Scheduling mechanism: (a) APScheduler-in-scheduler.py vs (b) orchestrator-tail-hook vs (c) dedicated module + scheduler hook.** Chose (c): dedicated module `backend/monitoring/silent_failure_watch.py` with cron registration in scheduler.py. Rationale already stated in Plan 10-01 alternatives_considered. Reinforcing here: (a) would add >50 lines to scheduler.py (already 286 lines, 5 jobs) and couple monitoring with pipeline execution; (b) misses the aggregate 24h view the watchdog needs (runs-are-per-run, alerts-are-per-day). (c) = watertight-boundary, R-13-compliant.

**Consumer of the watchdog — HTTP self-probe vs direct function call.** Chose direct function call (`from backend.db.operations import get_alerts_pipeline_health`). Per Plan 10-02 handoff: HTTP self-probe introduces auth complexity (require_auth dep in prod), rate-limit collision risk (60/min shared budget with external probes), and a self-DoS failure mode if the HTTP layer itself is the bottleneck. Direct call bypasses all three. Trade-off: watchdog doesn't validate the HTTP route itself — that's 10-02's own test suite responsibility.

**Cron frequency — 5 min vs 15 min vs 60 min.** Chose **60 minutes** default (config-overridable). Rationale: the 24h sliding window is the denominator; a 60-min polling interval gives ≤1h detection latency, well under the 2-month incident benchmark. 5-min would generate noise (alerts tend to fire in batches around scheduler cycles every 2h, not uniformly — a 5-min probe might catch a transient "0 alerts last 24h" window at specific hours). 60-min is operationally friendly and matches "check mid-afternoon, get a ping if broken" cognitive model. Config-overridable for future tuning.

**Alert message channel — primary slack_notifications channel vs separate override.** Chose override-capable: `slack_channel_override: Optional[str] = None` in config. Rationale: a P0 silent-failure alert should arrive in a high-visibility ops channel, not drown in the daily-digest alert channel. If override is None, falls back to existing `slack_notifications.webhook_url`. Operator can point override to a dedicated `#sentinel-p0` or leave null.

**Re-trigger suppression — fire every cycle vs debounce.** Chose **fire every cycle** (no suppression). Rationale: 60-min cadence + sustained silent-failure means ≤24 messages/day — acceptable. Suppression (e.g., "fire once, then mute 24h") requires state (debounce ledger table or in-memory) and creates a false-safety pattern if operator dismisses the first alert. Repeated alerts every hour = forcing function. If noise becomes an issue, Phase 18 hardening can add debounce.

**Meta-alert Block Kit payload shape — reuse send_alert_notification templates vs custom.** Chose custom. Rationale: `_send_slack` templates (P0/P1/P2) are alert-severity-based and expect an `AlertState` with `contributors`, `geo`, `environment_split` fields. A meta-alert has a fundamentally different payload: operational metrics (run counts, timestamps, phase reference). Custom payload with 3 blocks (header, section with metrics, context with phase ref) is cleaner than mangling AlertState-shaped input. Per context rule 4: new helper `send_meta_alert`, do NOT touch `_send_slack`/`send_alert_notification`.

**Config section naming — silent_failure_monitor vs pipeline_monitor vs silent_failure_alert.** Chose `silent_failure_monitor` — matches roadmap Phase 10 title ("Pipeline Silent-Failure Monitoring") and is unambiguous (monitor vs alert avoids confusion with "an alert about silent failures"). Consistent with the existing prose "silent-failure" in STATE.md, ROADMAP.md, PROJECT.md.
</alternatives_considered>

    ```
    Edge cases:
        * pipeline_runs=0 AND alerts=0 => zero-state (app just started or
          scheduler off) => NOT triggered.
        * pipeline_runs=0 AND alerts>0  => impossible in practice (alerts come
          from runs) => treat as NOT triggered (data anomaly, log WARNING).
        * pipeline_runs>0 AND alerts>0  => healthy => NOT triggered.
    """
    from __future__ import annotations

    import json
    import logging
    import os
    import time
    from datetime import datetime, timezone
    from typing import Optional
    from urllib.error import URLError
    from urllib.request import Request, urlopen

    from backend.db.operations import get_alerts_pipeline_health
    from backend.utils.config_loader import get_config
    from backend.utils.logger import get_logger

    logger = get_logger(__name__)

    META_ALERT_EMOJI = ":rotating_light:"
    META_ALERT_HEADER = "PIPELINE SILENT FAILURE"
    PHASE_REF = "Phase 10 MONITOR-02"


    def _resolve_webhook_url() -> Optional[str]:
        """env SLACK_WEBHOOK_URL first; then config.silent_failure_monitor.slack_channel_override;
        then config.slack_notifications.webhook_url (YAML fallback, same pattern as notifier.send_daily_digest)."""
        url = os.environ.get("SLACK_WEBHOOK_URL")
        if url:
            return url

        # Override from silent_failure_monitor section takes precedence over generic slack_notifications
        try:
            cfg = get_config()
            override = cfg.silent_failure_monitor.slack_channel_override
            if override:
                return override
        except Exception as e:
            logger.warning("silent_failure_monitor config access failed: %s", e)

        # Final fallback: generic slack_notifications.webhook_url from YAML
        try:
            import yaml
            from pathlib import Path
            config_path = Path(__file__).resolve().parent.parent.parent / "config" / "alerting_rules.yaml"
            with open(config_path, "r") as f:
                data = yaml.safe_load(f)
            return data.get("slack_notifications", {}).get("webhook_url")
        except Exception as e:
            logger.warning("Failed to load webhook from slack_notifications config: %s", e)
            return None


    def _build_meta_alert_blocks(metrics: dict) -> list:
        """Build Block Kit payload for a P0 meta-alert.

        Distinct from notifier._build_slack_blocks_p0 (which is alert-shaped with
        contributors/geo/env). Meta-alert body cites run/alert counts + last alert
        timestamp + phase reference.
        """
        now_utc = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M UTC")
        last_alert_text = metrics.get("last_alert_at") or "(never)"
        body_text = (
            f"*{META_ALERT_EMOJI} P0 {META_ALERT_HEADER}*\n\n"
            f"*Pattern:* `pipeline_runs_last_24h > 0 AND alerts_last_24h == 0`\n"
            f"*Pipeline runs (24h):* {metrics['pipeline_runs_last_24h']}\n"
            f"*Alerts written (24h):* {metrics['alerts_last_24h']}\n"
            f"*Last alert at:* {last_alert_text}\n\n"
            f"_This is the same divergence pattern that caused the 2026-01-22 → "
            f"2026-04-22 silent-failure incident. Investigate immediately._\n\n"
            f"Watchdog: {PHASE_REF} | Now: {now_utc}"
        )
        return [
            {
                "type": "header",
                "text": {"type": "plain_text", "text": f"{META_ALERT_EMOJI} {META_ALERT_HEADER} (P0)"},
            },
            {"type": "divider"},
            {
                "type": "section",
                "text": {"type": "mrkdwn", "text": body_text},
            },
            {
                "type": "context",
                "elements": [
                    {"type": "mrkdwn", "text": f"Source: {PHASE_REF} watchdog | Endpoint: /api/health/alerts-pipeline"},
                ],
            },
        ]


    def send_meta_alert(metrics: dict, _webhook_override: Optional[str] = None) -> bool:
        """POST a P0 meta-alert Block Kit payload to Slack.

        Returns True on successful 200 response; False if webhook unconfigured,
        auth failed, or all retries exhausted. Does NOT raise — silent-failure
        watchdog must never crash the scheduler.

        `_webhook_override` is for testing only (bypasses config resolution).
        """
        webhook_url = _webhook_override or _resolve_webhook_url()
        if not webhook_url:
            logger.warning(
                "send_meta_alert: webhook unconfigured (env SLACK_WEBHOOK_URL missing, "
                "config.silent_failure_monitor.slack_channel_override null, "
                "config.slack_notifications.webhook_url missing). Skipping Slack send."
            )
            return False

        blocks = _build_meta_alert_blocks(metrics)
        payload_json = json.dumps({"blocks": blocks}).encode("utf-8")

        max_retries = 3
        for attempt in range(max_retries):
            try:
                req = Request(
                    webhook_url,
                    data=payload_json,
                    headers={"Content-Type": "application/json"},
                    method="POST",
                )
                with urlopen(req, timeout=10) as resp:
                    if resp.status == 200:
                        logger.info(
                            "send_meta_alert: Slack POST succeeded (attempt %d/%d) metrics=%s",
                            attempt + 1, max_retries, metrics,
                        )
                        return True
                    elif resp.status >= 500:
                        delay = 2 ** attempt
                        logger.warning(
                            "send_meta_alert: Slack %d (attempt %d/%d), retrying in %ds",
                            resp.status, attempt + 1, max_retries, delay,
                        )
                        time.sleep(delay)
                    else:
                        logger.warning("send_meta_alert: Slack returned %d", resp.status)
                        return False
            except (URLError, OSError) as e:
                if attempt < max_retries - 1:
                    delay = 2 ** attempt
                    logger.warning(
                        "send_meta_alert: send failed (attempt %d/%d), retrying in %ds: %s",
                        attempt + 1, max_retries, delay, e,
                    )
                    time.sleep(delay)
                else:
                    logger.error("send_meta_alert: all retries exhausted: %s", e)
                    return False
        return False


    def check_silent_failure() -> dict:
        """Query 24h metrics and classify as triggered/healthy/zero-state.

        Returns {
            triggered: bool,
            reason: str,        # 'silent_failure' | 'healthy' | 'zero_state' | 'data_anomaly'
            metrics: dict,      # forwarded from get_alerts_pipeline_health()
        }
        """
        metrics = get_alerts_pipeline_health()
        prl = metrics["pipeline_runs_last_24h"]
        al = metrics["alerts_last_24h"]

        if prl == 0 and al == 0:
            reason = "zero_state"
            triggered = False
        elif prl > 0 and al == 0:
            reason = "silent_failure"
            triggered = True
        elif prl == 0 and al > 0:
            reason = "data_anomaly"  # alerts without runs — investigate but don't panic
            triggered = False
            logger.warning(
                "check_silent_failure: data_anomaly — alerts_last_24h=%d but pipeline_runs_last_24h=0",
                al,
            )
        else:
            reason = "healthy"
            triggered = False

        return {"triggered": triggered, "reason": reason, "metrics": metrics}


    def run_watch_cycle() -> dict:
        """APScheduler entry point. Runs one watchdog cycle.

        Never raises — logs and continues. Scheduler must keep running even
        if the watchdog itself errors (the whole point is to surface problems,
        not to become one).

        Returns result dict for test visibility / test assertions.
        """
        logger.info("silent_failure_watch: cycle start")
        try:
            result = check_silent_failure()
        except Exception as e:
            logger.exception("silent_failure_watch: check_silent_failure raised")
            return {"triggered": False, "reason": "watchdog_error", "metrics": {}, "error": str(e)}

        if result["triggered"]:
            try:
                sent = send_meta_alert(result["metrics"])
                result["slack_sent"] = sent
            except Exception as e:
                logger.exception("silent_failure_watch: send_meta_alert raised")
                result["slack_sent"] = False
                result["slack_error"] = str(e)
        else:
            result["slack_sent"] = False

        logger.info(
            "silent_failure_watch: cycle complete — triggered=%s reason=%s metrics=%s",
            result["triggered"], result["reason"], result["metrics"],
        )
        return result
    ```

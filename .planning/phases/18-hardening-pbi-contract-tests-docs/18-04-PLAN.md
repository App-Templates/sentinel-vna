       ## v1.3 PBI ↔ Sentinel Gap Disclosure

       Eight known gap classes are documented below per CONTEXT.md D-12 (`.planning/phases/18-hardening-pbi-contract-tests-docs/18-CONTEXT.md`). Each entry maps the gap to the phase that closed it (or will close it). Authoritative requirement IDs in `.planning/REQUIREMENTS.md`; phase order in `.planning/ROADMAP.md`.

       ### Gap 1 — OM (Open Market) revenue taxonomy delta

       PBI's "Open Market" classification includes ~€40k of revenue that Sentinel classifies as `DIRECT` per `config/sell_type_proxy.yaml`. This is an intentional taxonomy difference, not a measurement error. PBI groups by deal-vs-no-deal at the auction layer; Sentinel groups by `channel_group` at the ETL layer.

       - **Closing phase:** Phase 17.1 (Publisher Mapping Correction) — documented via `config/sell_type_proxy.yaml` annotation block + Marco's email verbatim cross-reference (MAP-06)
       - **Impact:** Mondadori Feb 2026 OM revenue: Sentinel €50k vs PBI €90k (~44% delta). Reconciles when Sentinel applies PBI's auction-layer reclassification — not in v1.3 scope.
       - **Reference:** `.planning/REQUIREMENTS.md` §MAP-06 + `.planning/phases/17.1-publisher-mapping-correction/17.1-SUMMARY.md`

       ### Gap 2 — eCPM / RPM denominator definitions

       eCPM = revenue / impressions × 1000. PBI sometimes reports gross-revenue / impressions, sometimes net-revenue (post rev-share 60%) / impressions, depending on the report. Sentinel exposes both via the gross/net toggle (CORR-03, shipped Phase 14). For per-report PBI parity, use the denominator that matches the specific PBI dashboard being compared.

       - **Closing phase:** Phase 18 (this phase) — documented here; no code change required
       - **Impact:** Side-by-side gross + net display (CORR-03) lets the operator pick the denominator at view time; no PBI parity failure attributable to denominator definition.
       - **Reference:** `.planning/REQUIREMENTS.md` §CORR-03 + Phase 14 SUMMARY

       ### Gap 3 — Hourly YoY synthetic vs measured (Phase 17.3 H6 root cause + Phase 17.4 forward fix)

       Pre-Phase-17.3, BACKTEST mode in `backend/agents/data_fetcher_real.py` had a tz-mismatch bug: `current_ts` was tz-aware while parquet timestamps were tz-naive; pandas comparison silently returned False; fallback to synthetic data fired without warning. Both Sample 1 and Sample 2 of Marco's audit ran into this. Phase 17.3 landed the +13-line fix; Phase 17.4 closed Sample 1 byte-perfect via Path A (`/api/metrics/network-totals` extension), Sample 2 awaits Phase 21 Athena.

       - **Closing phase (root cause):** Phase 17.3 (Alert Revenue Calc Audit) — shipped 2026-05-21
       - **Closing phase (Sample 1 forward fix):** Phase 17.4 (D2 Closure Tecnica) — shipped 2026-05-21
       - **Closing phase (Sample 2 + remaining channels):** Phase 21 v1.4 (pending)
       - **Impact:** Pre-fix synthetic alerts (~200 total) marked `deprecated=1` with reason `synthetic-era pre-H6-fix` via Migration 006 (Phase 17.4 D2CLOSE-03).
       - **Reference:** `.planning/REQUIREMENTS.md` §AUDIT-01/02/03 + §D2CLOSE-01..04 + Phase 17.3 + 17.4 SUMMARYs

       ### Gap 4 — Fill rate denominator (measurable_impressions)

       PBI fill_rate = `measurable_impressions / bacino` (35.2% for Mondadori Feb 2026). Pre-v1.3, `etl_csv_to_parquet.py:187` dropped `measurable_impressions` from the parquet schema. Phase 08 SCHEMA-03 preserved it; fill rate now within 1.5 ppt of PBI.

       - **Closing phase:** Phase 08 (Schema Migration + ETL Extensions) — shipped 2026-04-23
       - **Impact:** Fill rate matches PBI 35.2% within 1.5 ppt (verified by `scripts/test_mondadori_fill_rate_regression.py`).
       - **Reference:** `.planning/REQUIREMENTS.md` §SCHEMA-03 + Phase 08 SUMMARY

       ### Gap 5 — Top-50 publisher filter (Phase 17.4 Path A resolution)

       `daily_aggregated.parquet` applies a top-50-by-revenue publisher filter at the ETL layer (Phase 11 D1 hybrid). For PBI-parity at the alert-detail layer this caused 21% under-reporting on Sample 1 (€521 vs PBI €662). Phase 17.4 Path A reads `hour_kpi.csv` directly via `_compute_network_totals_for_channel` (bypass_top50=True), yielding byte-perfect €662.67 for GOOGLE_ADEX. The Path A branch is gated GOOGLE_ADEX-only by design — defense-in-depth via Phase 18 18-03 INV-6 source-grep regression.

       - **Closing phase:** Phase 17.4 (D2 Closure Tecnica) — shipped 2026-05-21

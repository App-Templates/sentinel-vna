# Phase 10.1 Plan 04: MAJOR-01 mode filter + MAJOR-03 temporal regression Summary

**One-liner:** `get_alerts_pipeline_health()` scoped to `mode='LIVE'` pipeline_runs, BACKTEST contamination eliminated; temporal boundary regression coverage added proving migration 004 fix holds.

## What Was Built

### Task 1: `AND mode='LIVE'` filter + BACKTEST regression tests (commit `ea4a548`)

**Fix (`backend/db/operations.py`):** Added `AND mode = 'LIVE'` to the `pipeline_runs` count query inside `get_alerts_pipeline_health()`. The existing query counted ALL pipeline_runs rows including Phase 09's 1442 BACKTEST backfill rows, inflating `pipeline_runs_last_24h` to 1447. This caused the watchdog to false-positive P0 (1447 pipeline runs + 0 alerts = watchdog fires), which forced the mitigation commit `bb34e36` disabling the watchdog entirely.

**Tests (`scripts/test_health_alerts_pipeline.py`):** Added `TestHealthEndpointModeFilter` class with 3 regression tests using tmpdb fixtures with proper `_set_db` / `_reset_db` helpers (matching the established `test_operations_idempotency.py` pattern):

- `test_pipeline_runs_last_24h_excludes_backtest_rows`: seeds 5 LIVE + 1442 BACKTEST rows, asserts result=5
- `test_pipeline_runs_last_24h_zero_when_only_backtest`: seeds 10 BACKTEST rows, asserts result=0
- `test_alerts_last_24h_unchanged_by_mode_filter`: confirms alerts query scope is independent; mode filter only applies to pipeline_runs

Also updated `test_last_alert_at_is_null_or_iso8601` comment to reflect that the live DB is now 100% canonical space-sep per MONITOR-04 (Plan 10.1-03).

### Task 2: Temporal boundary regression tests (commit `d5c597c`)

**Tests (`scripts/test_health_alerts_pipeline.py`):** Added `TestHealthEndpointTemporalBoundary` class with 3 regression tests:

- `test_temporal_query_bit_identical_on_canonical_rows`: 3 canonical rows (0.5h, 12h, 23.5h ago) all correctly counted within 24h window — confirms space-sep string comparison against `datetime('now','-1 day')` is correct post-migration
- `test_temporal_query_misses_t_separator_rows_pre_migration`: documents the pre-migration bug class — T-separator rows have T (0x54) > space (0x20) at separator position, so they sort above the space-sep cutoff and ARE over-counted; canonical rows always compare correctly; asserts total = per-format split
- `test_max_created_at_returns_true_latest_across_canonical_rows`: seeds 3 canonical rows (1h, 5h, 10h ago), asserts `last_alert_at` equals the 1h-ago row's exact microsecond string

## DB Patching Approach

The plan suggested `patch("backend.db.database.DB_PATH", db_path)` but the actual module uses `_DB_PATH` (module-level with leading underscore) plus a thread-local connection cache. The established project pattern (from `test_operations_idempotency.py`) is:

```python
os.environ["VNA_DB_PATH"] = db_path
db_mod._DB_PATH = None                 # force re-read on next get_db call
db_mod._local.connection = None        # close thread-local cached connection
```

Used this pattern via `_set_db(db_path)` / `_reset_db()` helper functions, called in `setUp` / `tearDown`. No deviation in behavior — same isolation guarantee, correct implementation.

# Phase 10.1 Plan 02: Write-Path Canonical Format Unification Summary

**One-liner:** Unified all `alerts.created_at` write callsites to space-sep naive UTC microseconds via `_canonical_utc_now()` helper in notifier.py + inline `isoformat(sep=' ', timespec='microseconds')` in operations.py, added `(saved, is_new)` tuple return to `_save_to_db`, and extended HARD-03 drift gate with 4 new format-invariant assertions.

## What Was Built

### Task 1: operations.py canonical format (commit `c7c2a7b`)

- `create_alert`: both `created_at` and `updated_at` now use `.isoformat(sep=' ', timespec='microseconds')` with `tzinfo` stripping for aware inputs
- `record_pipeline_run`: `created_at` write now uses `.isoformat(sep=' ', timespec='microseconds')`
- Out-of-scope callsites (`create_event`, `create_recheck`, `get_pending_rechecks`) annotated with `# NOTE (10.1)` comments
- 3 new TDD tests in `TestCreateAlertCanonicalFormat` (RED pre-fix → GREEN post-fix)

### Task 2: notifier.py canonical format + is_new signal (commit `fe02601`)

- `_canonical_utc_now()` helper defined after imports, before `_save_to_pending_notifications`
- `_save_to_pending_notifications`: `created_at` write uses `_canonical_utc_now()`
- `_save_to_db` rewritten:
  - Returns `tuple[bool, bool]` `(saved, is_new)` instead of `bool`
  - UPDATE path returns `(True, False)` — dedup, no new row
  - INSERT path returns `(True, True)` — new alert row
  - Error path returns `(False, False)`
  - Both UPDATE and INSERT paths use `_canonical_utc_now()` for timestamp writes
- `notifier_agent` updated: `saved, is_new = _save_to_db(state)` unpacks tuple; `delivery_status["db_new_row"] = is_new` added
- `delivery_status` initialized with `"db_new_row": False`
- 3 new TDD tests in `TestNotifierSaveToDbCanonicalFormat` (RED pre-fix → GREEN post-fix)

### Task 3: HARD-03 drift gate (commit `38a8b15`)

- `TestCreatedAtFormatInvariant` class added to `scripts/test_models_sync.py`
- 4 new tests:
  - `test_a01`: notifier.py defines `_canonical_utc_now`, no aware isoformat in `_save_to_pending_notifications` or `_save_to_db`, helper called ≥ 2 times in `_save_to_db`
  - `test_a02`: `create_alert` body contains ≥ 2 canonical isoformat calls
  - `test_a03`: `record_pipeline_run` body contains canonical isoformat, no bare `.isoformat()`
  - `test_a04`: regex literal `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{6}$` byte-identical across `apply_migration_004.py`, `test_migration_004_apply.py`, `test_operations_idempotency.py`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] test_save_to_db_update_writes_canonical — seeded alert outside dedup window**
- **Found during:** Task 2, GREEN phase
- **Issue:** Test seeded alert with timestamp `datetime(2026, 1, 1, 9, 0, 0)` which is months in the past. `find_open_alert()` filters `timestamp >= datetime('now', '-6 hours')` so the seeded alert was not found, causing `_save_to_db` to take the INSERT path instead of UPDATE → `new_row` was not None → assertion failure.
- **Fix:** Changed seeded alert timestamp to `datetime.utcnow()` (current time) so it falls within the 6-hour dedup window. Alert ID derived from current time via strftime.
- **Files modified:** `scripts/test_operations_idempotency.py`
- **Commit:** `fe02601` (inlined into the TDD GREEN commit — fix was in the test, not production code)

**2. [Rule 1 - Note] Success criterion grep count = 4 vs expected ≥ 5**
- **Found during:** Post-task verification
- **Issue:** Plan success criterion expected ≥ 5 grep matches for `.isoformat(sep=' ', timespec='microseconds')` across both files. Helper approach yields 4 literal occurrences (1 in `_canonical_utc_now()` + 3 in `operations.py`).
- **Assessment:** Functionally equivalent — helper centralizes the format, HARD-03 `test_a01` validates ≥ 2 `_canonical_utc_now` calls in `_save_to_db` body. The behavioral contract is met; the grep count was a planning estimate for inline approach.
- **Decision:** No code change needed — acceptance is via test gate, not grep count.

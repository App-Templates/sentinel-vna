# Phase 10.1 Plan 06: send_meta_alert Retry Rewrite Summary

**One-liner:** Rewrote `send_meta_alert` retry loop to correctly distinguish `HTTPError` (429/5xx/4xx) from `URLError`, honor `Retry-After` on 429, and eliminate dead-code branches; MONITOR-07 CLOSED with 5 new TDD tests (RED pre-fix, GREEN post-fix).

## What Was Built

### Task 1: TDD rewrite of send_meta_alert + 5 new retry-semantics tests (commit `fb3165b`)

**Root cause fixed (MAJOR-02 + WR-01):**

The old retry loop caught `except (URLError, OSError)`, which also catches `HTTPError` (because `HTTPError IS-A URLError`). This meant:
- `resp.status >= 500` branch was dead code — `urlopen()` raises `HTTPError` for any non-2xx, so this branch was never reached
- `resp.status != 200` fallback `return False` was also dead code
- HTTP 429 rate-limit responses were caught as generic `URLError` and retried without honoring `Retry-After`
- HTTP 4xx non-429 responses were retried 3 times instead of failing fast

**New retry structure per D-10.1-06:**

```python
except urllib.error.HTTPError as e:
    if e.code == 429:          # honor Retry-After header
    elif e.code >= 500:        # exponential backoff retry
    else:                      # 4xx non-429: non-retriable, return False
except urllib.error.URLError as e:
    # network layer: retry with exponential backoff
```

**Import changes:**
- Removed unused `import logging` (IN-01 closed)
- Added `import urllib.error` + changed `from urllib.error import URLError` to `from urllib.error import HTTPError, URLError`

## Decisions Made

### D-17.1-03-A — Single-expression arrow function (not braced block)

**Decision:** The Phase 17 handler was a 4-line braced block hosting the guard. Removing the guard collapses the body to a single navigation statement. The arrow function now uses single-expression form `(row) => navigate(...)` rather than `(row) => { navigate(...) }`.

**Rationale:** Single-expression form is the idiomatic TypeScript/React style for handlers that perform a single action. Reduces line count, removes the need for an explicit `return` (implicit in single-expression arrow), and aligns with the rest of the file's style (e.g., column `render` props are mostly single-expression arrows). R-13 maintainability.

### D-17.1-03-B — encodeURIComponent added defensively despite no current spaces in IDs

**Decision:** `encodeURIComponent(row.publisher_id)` wraps the interpolation even though Wave 2a's `/api/publishers/top?year=2025&limit=100` response shows publisher_ids that mostly render as single-word (e.g., `Mondadori`, `Vocento`, `Mediamond`, `Dorvan`).

**Rationale:** PBI-normalized publisher names in Marco's mapping CAN include spaces and accents — verified inline in the Wave 2a SUMMARY numeric-proof table: `Prensa Ibérica`, `Grupo Godó`, `Unidad Editorial`, `El Español`. Without encodeURIComponent, the URL `/publishers/Prensa Ibérica` would tokenize differently in react-router (space-splitting risk) and the percent-encoded form `/publishers/Prensa%20Ib%C3%A9rica` is the safe canonical representation. This is pre-emptive defense for the existing data — not speculative.

**Verification:** `encodeURIComponent('Prensa Ibérica')` returns `'Prensa%20Ib%C3%A9rica'` (browser-tested via DevTools console; standard ECMA-262 §B.2.1.2 spec).

### D-17.1-03-C — Frontend comment uses 'Mondadori_family' literal (historical context allowed)

**Decision:** The 6-line intent comment uses the literal string `"Mondadori_family"` to explain what Phase 17 was guarding against.

**Rationale:** The Wave 2a static-content gate (`scripts/test_publishers_top_mapping_applied.py::TestPublishersTopFileContent::test_no_mondadori_family_literal_in_source`) is scoped to `backend/api/publisher_routes.py` ONLY — verified by inspection of the test's `READ_PATH` constant. The frontend file has no equivalent gate. The literal in a comment provides documentation value (explains the rationale for the deleted code) without violating any active CI invariant. If Wave 5 or a future hardening plan adds a cross-codebase literal-absence invariant, the comment can be paraphrased per Wave 2a D-17.1-02a-B precedent (comment paraphrasing without trigger literal).

### D-17.1-03-D — No frontend test added (out of plan scope)

**Decision:** No `frontend/src/pages/PublishersPage.test.tsx` or equivalent test file added.

**Rationale:** Plan's `<objective>` explicitly states "no new UI components, no styling changes, no i18n changes, no router changes. Just remove the dead guard." `read_first` instructed a grep for existing tests pinning the guard — none found (`grep -rn "_family" frontend/src/` returned only the line being deleted; no `frontend/tests/` directory; no `*.test.*` or `*.spec.*` files anywhere in `frontend/src/`).

## SQL Parameterization Safety Note

The IN-clause expansion uses **only** safe primitives:

```python
ids = list(publisher_id)  # backward-compat normalization
placeholders = ",".join("?" * len(ids))  # produces only "?" and "," chars
conn.execute(f"... WHERE publisher_id IN ({placeholders}) ...", (*ids, limit))
```

The f-string interpolates ONLY the placeholder pattern (`"?,?,?"`), never user input. The actual values pass through sqlite3's parameterized binding. ASVS V5.3.4 (SQL parameterization) is satisfied — same safety class as the original `WHERE publisher_id = ?` form, just with N placeholders instead of 1.

## Decisions Made

### D-17.1-02b-A — Helper colocation in publisher_routes.py (not factored)

**Decision:** `_resolve_publisher_ad_units` lives in `publisher_routes.py` alongside `_load_ad_unit_mapping`. routes.py imports via `from backend.api.publisher_routes import _resolve_publisher_ad_units` inside the async handler body.

**Rationale:** The plan's `<interfaces>` block authorized factoring to a new `publisher_mapping.py` module ONLY IF circular-import risk emerged at runtime. None did: routes.py never had a top-of-module import from publisher_routes.py prior to this plan, and the new dependency is introduced via local import inside the async function (zero top-of-module cycle risk). Single-file location keeps helper + 3 in-file callers reviewable in one editor scroll (R-13 maintainability). The 2 cross-module callers (routes.py) live in a single logical block (both SQL endpoints in the same file), so the cross-module hop is also localized.

### D-17.1-02b-B — Defensive None-fallback in _resolve_publisher_ad_units

**Decision:** When `_load_ad_unit_mapping()` returns None (file missing / parse error), `_resolve_publisher_ad_units(name)` returns `{name}` — a singleton set containing the input as-is.

**Rationale:** Preserves backward-compat with environments where the xlsx hasn't been deployed yet. The mapping IS deployed in all current environments (Wave 1 MAP-01 committed it to git), but the defensive path documents intent for fresh clones, partial deploys, or future test environments that may not have the file. Empty set would yield 404 for ALL drilldown requests in such environments — strictly worse UX. Singleton set produces the same behavior as the pre-Phase-17.1 code path (exact-match on raw name).

### D-17.1-02b-C — sys.modules shim extension of D-17.1-02a-C

**Decision:** `_inject_scheduler_shim()` installs a stand-in `backend.scheduler.scheduler` module providing only `is_scheduler_running` (the single symbol `backend.api.routes` imports from scheduler). Called BEFORE the `import backend.api.routes` line in `_build_minimal_app(include_routes_module=True)`.

**Rationale:** Wave 2a's minimal-FastAPI-app pattern (D-17.1-02a-C) only covered `publisher_routes` (which has no scheduler dependency). Plan 02b also tests `routes.py`, which transitively imports `langgraph` via `backend.scheduler.scheduler → backend.workflow.graph`. langgraph is absent in the local Python environment (documented Wave 1 SUMMARY "Issues Encountered"). The shim is idempotent — if the real module loads cleanly (CI environment), the function returns early without installing the shim. Pattern is reusable for any future test that needs to load routes.py without the full backend.main dependency stack.

### D-17.1-02b-D — Rule 1 test-fixture fix bundled into GREEN-parquet

**Decision:** `test_mondadori_aggregates_npa_variant` updated from calendar-year filter (`df["date"].dt.year == 2025`) to ISO-year filter (`iso_cal.year == 2025`) to match `_aggregate_weekly`'s semantic. Committed in GREEN-parquet `1190bf3`.

**Rationale:** The original test compared the drilldown's ISO-year output against a raw calendar-year sum, producing a 4-day boundary mismatch (€18,094.32, ~1.6%) on late-Dec 2025 dates whose ISO week belongs to ISO year 2026 (specifically 2025-12-29, 30, 31 — checked via inspection). The drilldown's behavior is correct; only the test's expected value was misaligned. Same atomic-commit precedent as Wave 2a D-17.1-02a-A: the strengthening lives in the same commit as the originating bug — committing the broken test scaffold separately would leave the suite RED between commits, violating R-03.

### D-17.1-02b-E — Permissive signature for get_publisher_feedback_history

**Decision:** Signature is `publisher_id: str | Iterable[str]` (typed loosely as `publisher_id` with runtime `isinstance(str)` check). Smoke-tested 4 input shapes.

**Rationale:** Backward-compat with any future caller that still has only a single raw id (e.g., a hypothetical legacy script). Smoke tests verify:
- `get_publisher_feedback_history("id", 1)` works → returns list
- `get_publisher_feedback_history(["id1", "id2"], 5)` works → returns list
- `get_publisher_feedback_history({"id1", "id2"}, 5)` works → returns list
- `get_publisher_feedback_history([], 5)` returns `[]` (no SQL fired)

Strict set-only signature would force every caller to wrap a singleton — net negative ergonomics for a 1-line tolerance.

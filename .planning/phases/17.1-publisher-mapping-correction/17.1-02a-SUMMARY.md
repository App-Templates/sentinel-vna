## Decisions Made

### D-17.1-02a-A — W-04 test strengthened beyond plan spec (Rule 1 auto-fix)

**Decision:** The plan's literal `src.find('_load_ad_unit_mapping()')` pattern matches the `def _load_ad_unit_mapping():` line at module-level (offset 6726, before any groupby). That would yield a trivial false-pass even when the function is never CALLED. Strengthened the test to (a) require `src.count('_load_ad_unit_mapping()') >= 2` (def + at least one call) and (b) assert `rfind` (LAST occurrence — the call) precedes the first groupby.

**Rationale:** R-11 + R-13: a test that can be satisfied without the implementation doing its job is worse than no test at all (false confidence). The strengthened version is a strict superset of the plan spec and catches both the RED state (only 1 occurrence — def alone) and any future regression that removes the call. Committed in RED `068ae8a` so the strengthening lives in the same commit as the originating scaffold.

### D-17.1-02a-B — Comment paraphrasing to satisfy literal-absence invariant (Rule 1 auto-fix)

**Decision:** Initial edit left 2 comment references mentioning `MONDADORI_FAMILY` / `Mondadori_family` as historical context. These would have failed `test_no_mondadori_family_literal_in_source`. Rewrote the comments to convey the same warning ("Phase 17 hardcoded synthetic-family aggregation block which wrongly merged Mediamond and Mondocore into Mondadori — Marco audit 2026-05-18") without the trigger literals.

**Rationale:** The plan's must_have asserts ZERO occurrences in source. Comments and code are not distinguished by the static-content gate (and shouldn't be — a comment with the trigger literal still leaks the synthetic-family idea into future grep-driven refactors). The historical context value is preserved by paraphrasing; the static-content invariant is respected.

### D-17.1-02a-C — Minimal-FastAPI-app test pattern (Rule 3 auto-fix, bundled atomically into GREEN per R-03)

**Decision:** Replaced `from backend.main import app` with a minimal FastAPI app constructed in `setUpClass` containing only `publisher_routes.router` + slowapi rate-limiter wiring.

**Rationale:** `backend.main` transitively imports `backend.scheduler.scheduler` which imports `backend.workflow.graph` which imports `langgraph` — and `langgraph` is absent in this local Python environment (pre-existing gap documented in Wave 1 SUMMARY's "Issues Encountered"). The `from backend.main import app` raises `ModuleNotFoundError` which propagates as a test ERROR (not SkipTest) — that breaks the plan's acceptance criterion `python3 -m unittest scripts.test_publishers_top_mapping_applied -v exits 0 with OK (or data-dependent SKIP)`. The minimal-app pattern exercises the actual route end-to-end while bypassing the unrelated dependency stack. Same pattern works in CI (where langgraph IS available — we just don't import backend.main). Bundled into the GREEN feat commit per Wave 1 D-17.1-01-D precedent: committing a broken test scaffold separately would leave the suite red between commits, violating R-03.

### D-17.1-02a-D — Mondocore conditional in plan test scaffold preserved as-is (no action needed)

**Decision:** The plan's `test_mondadori_mediamond_mondocore_are_separate` wraps Mondocore checks in `if "Mondocore" in ids`. This is correct as-is: in the live 2025 parquet `Adgage_mondocore` has €0 revenue, so the mapped `Mondocore` row does not appear in top-100. The conditional handles this gracefully.

**Rationale:** Documented here so a future executor doesn't read "Mondocore absent from top-100" as a mapping failure. The mapping IS being applied (verified: dict[Adgage_mondocore] = Mondocore exists in the loader output); the source data simply has no revenue for that publisher in the current year. If 2026 data added revenue for Adgage_mondocore, Mondocore would appear; the test would then exercise the "SEPARATE from Mondadori" assertion.

### D-17.1-02a-E — EXCLUDED_PUBLISHER_CLUSTERS scoped per-function

**Decision:** Defined `EXCLUDED_PUBLISHER_CLUSTERS = {"OLD", "test"}` inside `get_top_publishers` (line 316), reused at the df_ch_year filter (line 383) without redefining. Did NOT lift to module level.

**Rationale:** Single source of truth lives next to both call sites where it can be reviewed in context. Module-level lifting would risk drift with any future drilldown handler that might want a different exclusion policy (e.g., drilldown to a specific OLD publisher for forensic audit). Adjacent definition + comment is clearer than a module constant at this scale.

<objective>
Close MONITOR-11: fix the CR-01 critical finding from `10.1-REVIEW.md` — `send_daily_digest`
builds its 24h cutoff with `datetime.now(timezone.utc).isoformat()` (aware T-separator) while
`pending_notifications.created_at` is written in canonical space-sep naive UTC microseconds
via `_canonical_utc_now()`. SQLite does a byte string compare; `' '` (0x20) sorts BELOW `'T'`
(0x54), so freshly-queued P1/P2 alerts silently drop from the digest for the first ~20h of
each day. This is the same MAJOR-NEW-01 bug class migration 004 fixed for `alerts.created_at`,
left in a sibling callsite. Then extend the HARD-03 drift gate (`TestCreatedAtFormatInvariant`)
to cover `send_daily_digest` so the regression cannot return.

Purpose: P1/P2 alerts must appear in the daily digest on the day they fire, not the next day.
The HARD-03 extension ensures Phase 10.3+ refactors cannot reintroduce the aware-T regression.

Output: `_canonical_utc_cutoff(hours_ago)` helper added to `notifier.py`; `send_daily_digest`
SELECT + DELETE both use it; `TestCreatedAtFormatInvariant` gains `test_a05_send_daily_digest_uses_canonical_cutoff`
that asserts the helper is used and the aware-T pattern is absent.

# Phase 10.2 Plan 03: Atomic _restore in All 4 Migration Drivers (MONITOR-14 / WR-03) Summary

**One-liner:** Replace the unlink-then-write `_restore` pattern with backup-to-temp-path + `os.replace(tmp, dst)` so a SIGKILL/OOM/power-loss mid-restore leaves the live DB at its pre-failure state instead of absent or empty; applied symmetrically across all 4 migration drivers.

## What Was Built

Closed MONITOR-14 (WR-03 from Phase 10.1 REVIEW): the previous `_restore` body unlinked the live DB before opening the new `sqlite3.connect(dst)` for `bak_conn.backup(dst_conn)`. A kill in the narrow window between `dst.unlink()` and the backup completing left the live DB either absent or empty (just-created empty SQLite file). Recovery required manual `cp` from the `.bak`. Because `_restore` is invoked exclusively from already-failing apply or verify paths, a second failure here compounded the operator-facing incident.

Fix applied (identical body in all 4 drivers):

```python
def _restore(bak: Path, dst: Path) -> None:
    """Restore the live DB atomically: backup to temp path, then atomic-rename.
    The live DB path is always either the pre-failure state (if killed before
    os.replace) or the fully restored state (if killed after) — never absent or
    partial. MONITOR-14 / WR-03 (Phase 10.2 Plan 03).
    """
    for suffix in ("-wal", "-shm"):
        stale = dst.with_name(dst.name + suffix)
        if stale.exists():
            stale.unlink()

    tmp = dst.with_suffix(dst.suffix + ".restore.tmp")
    if tmp.exists():
        tmp.unlink()

    bak_conn = sqlite3.connect(str(bak))
    dst_conn = sqlite3.connect(str(tmp))
    try:
        bak_conn.backup(dst_conn)
    finally:
        dst_conn.close()
        bak_conn.close()

    os.replace(tmp, dst)
    _log(f"Restored {dst} from {bak} via sqlite3.backup() + atomic replace")
```

`os.replace` is atomic on POSIX same-filesystem moves — the live DB path either points to the original (if killed before `os.replace`) or to the fully restored backup (if killed after). It is never the empty file the pre-fix produced.

New `TestMigration004Restore` class with 2 regression tests:

- `test_restore_atomic_intermediate_failure_leaves_db_intact` — patches `sqlite3.connect` with a wrapper whose `.backup()` raises `RuntimeError` (simulating mid-restore kill); asserts `dst.exists()` and SHA-256 of `dst` is byte-identical to pre-restore. Verified RED pre-fix (post-kill SHA was `e3b0c44298fc...` = empty-file SHA, dst.unlink had run) and GREEN post-fix.
- `test_restore_success_replaces_dst_with_backup_contents` — sanity check on the happy path: mutate dst, call `_restore`, assert dst content matches the pre-mutation backup.

## Deviations from Plan

**Test mock pattern adjusted for Python 3.11 immutable types.** The plan specified `mock.patch.object(sqlite3.Connection, "backup", side_effect=...)`, which is the canonical pattern in older Python. Python 3.11 made `sqlite3.Connection` an immutable C type — calling that patch raises `TypeError: cannot set 'backup' attribute of immutable type 'sqlite3.Connection'`. Switched to patching `self.mod.sqlite3.connect` with a side-effect that returns a wrapper object whose `.backup()` raises. Identical simulation fidelity (the kill happens at the bak_conn.backup() boundary either way) and runtime-portable. The decision is captured in the test docstring + the `decisions` frontmatter block.

No deviation from the source-code change — the `_restore` body in all 4 drivers is verbatim per the plan.

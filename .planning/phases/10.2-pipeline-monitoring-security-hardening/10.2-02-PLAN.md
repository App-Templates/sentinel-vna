<objective>
Close MONITOR-13: bound `Retry-After` parsing in `send_meta_alert` to defend the silent-failure
watchdog against a DoS by a malicious or misconfigured upstream returning `Retry-After: 999999`
(~11.5 days). Per `10.1-REVIEW.md` §WR-02, the current code trusts the header value without a
cap — `time.sleep(int(retry_after))` would block the watchdog thread for the full duration,
and APScheduler `max_instances=1` would defer subsequent watchdog cycles indefinitely behind
the sleep. The watchdog is the last line of defense for silent failures (Phase 999.1 confirmed
LIVE pipeline silence since 2026-03-23 — operator accepts ~17 P0 pages/day on the rotated
webhook); starving the watchdog in a retry loop defeats its purpose.

Purpose: Watchdog availability is bounded by the cron cadence (60 min), not by an upstream-
controlled value. Defense-in-depth against a single malicious POST-response-header.

Output: `MAX_BACKOFF_SEC = 60` module constant; Retry-After clamp via `min(int(retry_after),
MAX_BACKOFF_SEC)`; defensive `e.headers or {}` guard (covers WR-06 partial); regression test
`test_send_clamps_excessive_retry_after` proving the cap with a 999999 fixture.
</objective>

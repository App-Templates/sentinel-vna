## Root Cause

`_save_to_pending_notifications` writes `created_at` via `_canonical_utc_now()` (e.g. `'2026-04-24 12:00:00.123456'`). `send_daily_digest` queried `WHERE created_at >= cutoff` with cutoff `'2026-04-23T12:00:00.123456+00:00'`. SQLite byte-compare: `' '` (0x20) < `'T'` (0x54), so `'2026-04-24 ...' >= '2026-04-23T...'` evaluated FALSE for the first ~20h of the day. P1/P2 alerts silently dropped from the digest until the T-vs-space ambiguity window resolved on day rollover. Same MAJOR-NEW-01 bug class as migration 004 fixed for `alerts.created_at`.

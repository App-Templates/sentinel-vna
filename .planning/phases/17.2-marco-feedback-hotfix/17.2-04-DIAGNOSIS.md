# B1 Diagnosis — Tabs 3, 4, 5 "Not Accessible" (Marco 2026-05-19)

## Marco's claim (verbatim)

> Alert > Non è più possibile accedere ai tab 3. Top Contributors, 4. Geo Breakdown, 5. Environment Split.

## Reproduction

The live frontend reads alert JSON from `frontend/dist/api/alerts/ALT-*.json`
(snapshot baked at Phase 17.1-04 deploy time, 2026-05-19/20). 238 individual
alert files inspected by aggregating tab-field shapes:

```
Total: 238 alert JSONs
  contributors == []         : 238  (100%)
  geo_breakdown == []        : 238  (100%)
  environment_split == null  : 238  (100%)
  environment_split == {}    : 0
  environment_split populated: 0
```

**Every alert in the production snapshot exhibits all three "empty" fields
simultaneously.** This explains why Marco hit the defect on every alert he
clicked — there is no alert in the live snapshot with populated
contributors / geo / env data. Whatever populates these fields downstream
(the LLM-driven payload enrichment introduced in earlier phases) has not
produced any populated alerts in the legacy backfill corpus that the v1.3
snapshot is built from.

Sample (every one of 8 spot-checked alerts identical shape):

```
ALT-20260123-010000-P2.json → {c: 0, g: 0, env: null}
ALT-20260123-040000-P2.json → {c: 0, g: 0, env: null}
ALT-20260323-130000-P2.json → {c: 0, g: 0, env: null}
```

## Per-tab analysis

### Tab 3 — Top Contributors

- **STEPS predicate** (`AlertDetailPage.tsx:47`): **none** — always visible in strip.
- **Render guard** (`AlertDetailPage.tsx:251`):
  `{currentStep === 'contributors' && <ContributorsSection contributors={alert.contributors} />}`
  → no short-circuit on empty array, so section renders.
- **Section empty-state** (`ContributorsSection.tsx`):
  `safeContributors = contributors ?? []` (line 13) → `DataTable` receives an
  empty array.
- **`DataTable` empty behavior** (`DataTable.tsx:53-58`): the table component
  has a centered "No data available" fallback that fires when `data.length === 0`:
  ```tsx
  if (data.length === 0) {
    return (<div className="py-12 text-center text-gray-500">{emptyMessage}</div>)
  }
  ```
- **Visible output today:** the section renders its `<Card>` header
  ("Step 3: Top Contributors" + Concentration: 0.0%) and a "No data available"
  paragraph from DataTable. **Tab is reachable AND renders SOMETHING.** But
  the concentration line ("Concentration (Top 3): 0.0%") is rendered with
  the amber color and may be visually confusing — it looks like a real
  computed value when in fact the absence of data is what makes it 0.
- **Root cause classification:** **(d) UX defect, secondary** — the tab IS
  reachable and DOES render. But the rendered content is half-bait
  ("Concentration 0.0%" looks like a measurement) and half-DataTable
  ("No data available") rather than a single coherent empty-state card
  that says "this alert has no contributor data".
- **Fix scope (minimum):** add an explicit early-return empty-state card
  mirroring `EnvironmentSplitSection.tsx` lines 22-37 — the section returns
  a `<Card>` with title + "No contributor data available" copy when
  `safeContributors.length === 0`. This eliminates the misleading
  Concentration line and matches the Env section's existing pattern.

### Tab 4 — Geo Breakdown

- **STEPS predicate** (`AlertDetailPage.tsx:49`): **none** — always visible.
- **Render guard** (`AlertDetailPage.tsx:257`):
  `{currentStep === 'geo' && <GeoBreakdownSection geoBreakdown={alert.geo_breakdown} />}`
  → no short-circuit.
- **Section empty-state** (`GeoBreakdownSection.tsx`):
  `safeGeoBreakdown = geoBreakdown ?? []` (line 15) → empty array flows into
  the `DataTable` AND into `<GeoBreakdownPieChart data={safeGeoBreakdown} />`.
- **`DataTable` empty behavior:** same as Tab 3 — "No data available".
- **PieChart empty behavior:** wrapped in `<ChartErrorBoundary height={260}>`,
  so even if the pie chart throws on empty input, the boundary swallows the
  error and shows its own fallback. (Not verified at this time whether the
  Recharts pie throws or renders an empty SVG, but the boundary makes either
  path safe.)
- **Visible output today:** `<Card>` with "Step 4: Geographic Breakdown"
  title + a 2-column grid: left side shows DataTable's "No data available";
  right side shows whatever the empty-pie path renders (likely an empty SVG
  or the ChartErrorBoundary fallback).
- **Root cause classification:** **(d) UX defect, secondary** — same family
  as Tab 3. Reachable, renders, but the layout is half-empty-table /
  half-empty-pie. Less misleading than Tab 3 (no fake "Concentration" line)
  but still not a clean "no data" card.
- **Fix scope (minimum):** add explicit early-return empty-state card
  mirroring `EnvironmentSplitSection.tsx` lines 22-37 — single "No geo data
  available" message in place of the two-column DataTable+PieChart grid
  when `safeGeoBreakdown.length === 0`.

### Tab 5 — Environment Split

- **STEPS predicate** (`AlertDetailPage.tsx:50`): **none** — always visible.
- **Render guard** (`AlertDetailPage.tsx:259`) — **THE SMOKING GUN**:
  ```tsx
  {currentStep === 'environment' && alert.environment_split && Object.keys(alert.environment_split).length > 0 && (
    <EnvironmentSplitSection environmentSplit={alert.environment_split} />
  )}
  ```
  When `environment_split` is `null` (which it is for **all 238** legacy
  alerts in the snapshot), the conjunction short-circuits to falsy and
  **NOTHING is rendered in the content area**.
- **EnvironmentSplitSection's own empty-state** (`EnvironmentSplitSection.tsx:22-37`):
  there IS a friendly "No environment data available." card already
  implemented inside the section. **But the parent guard at line 259
  prevents the section component from ever being invoked**, so that
  empty-state card never reaches the DOM.
- **Visible output today:** the tab strip shows "5. Environment Split" as
  CLICKABLE (no STEPS predicate to hide it). User clicks it. The
  `<Step Content>` div renders nothing inside (every other `currentStep`
  branch is falsy, and the `environment` branch's `&& ... && ...` chain
  short-circuits). The page below the tab strip is BLANK.
- **Root cause classification:** **(b) render-guard short-circuit at
  AlertDetailPage layer, defeating the child component's own empty-state
  handling.** Marco interpreted "tab clickable but blank content" as "tab
  not accessible" — defensible reading: the tab provides zero user value
  when clicked. Bug, full stop.
- **Fix scope (minimum):** drop the `&& alert.environment_split && Object.keys(...).length > 0`
  half of the render guard at AlertDetailPage:259. Pass
  `alert.environment_split ?? {}` (or update prop type to
  `Partial<Record<Environment, EnvironmentMetrics>> | null`) so the section
  receives a safely-typed empty value. The section's existing lines 22-37
  then render its own clean empty-state card.

## Recommended fix (Task 2)

1. **AlertDetailPage line 259:** simplify to
   ```tsx
   {currentStep === 'environment' && (
     <EnvironmentSplitSection environmentSplit={alert.environment_split ?? {} as Record<Environment, EnvironmentMetrics>} />
   )}
   ```
   The section component already handles `Object.keys(...).length === 0` per
   its existing lines 22-37. If TS objects to the empty-object cast (because
   `Record<Environment, EnvironmentMetrics>` is a total record), widen the
   prop type to `Partial<Record<Environment, EnvironmentMetrics>> | null`
   — but the section already guards `!environmentSplit || keys.length === 0`,
   so the prop is effectively optional and Partial is the type-honest fix.
2. **ContributorsSection:** insert early-return empty-state branch before the
   existing `return (<Card>...DataTable.../>...</Card>)` when
   `safeContributors.length === 0`. Card title preserved; body becomes
   "No contributor data available." Mirror pattern from EnvironmentSplitSection.
3. **GeoBreakdownSection:** same pattern as Contributors — early-return
   empty-state branch for `safeGeoBreakdown.length === 0`. "No geo data
   available." copy.
4. **EnvironmentSplitSection:** no change. Already correct; just no longer
   blocked from rendering by the parent.
5. **DataTable:** no change. It already has a default `emptyMessage = 'No data
   available'`. Phases 3 + 4 will now never invoke it with empty data
   (the early-return short-circuits first), so its empty-state remains a
   defensive fallback for OTHER consumers.

## Out of scope

- Backend payload-shape changes — the absence of contributors / geo / env
  data in the snapshot is owned by upstream enrichment, not this plan.
  Phase 17.3 / Plan 05 handles B2 (Triage Bacino + Coverage = 0) payload
  fixes; B1 is purely client-side: make the UI render a clean empty-state
  for every shape the backend may produce.
- Error-boundary redesign — `ChartErrorBoundary` already protects Tab 4
  from empty-pie crashes; no expansion needed.
- Tab-strip a11y / focus management — not in Marco's report; orthogonal.
- The "Concentration (Top 3): 0.0%" line in ContributorsSection — the
  early-return will skip its render path, so no dedicated fix needed.

## Root cause — contract drift on `_current` suffix (HYPOTHESIS iii VARIANT)

The producer at `backend/agents/environment_splitter.py:42-50` emits:

```python
environment_split[env_name] = {
    "revenue_current": ec.get("revenue", 0),
    "revenue_baseline": eb.get("revenue", 0),
    "delta_abs": ...,
    "delta_pct": ...,
    "bacino_current": ec.get("bacino", 0),       # ← _current suffix
    "bacino_baseline": eb.get("bacino", 0),
    "coverage_current": round(ec.get("coverage", 0), 4),  # ← _current suffix
    "coverage_baseline": round(eb.get("coverage", 0), 4),
}
```

The consumer at `frontend/src/components/alerts/TriageSection.tsx:43-46`:

```tsx
const totalBacino = envEntries.reduce((s, [, m]) => s + (m.bacino ?? 0), 0)
//                                                       ^^^^^^^^^ undefined → 0
const avgCoverage = envEntries.length > 0
  ? envEntries.reduce((s, [, m]) => s + (m.coverage ?? 0), 0) / envEntries.length
  //                                     ^^^^^^^^^^^ undefined → 0
  : 0
```

The TypeScript type `EnvironmentMetrics` at `frontend/src/types/alert.ts:197-204` declares:

```ts
export interface EnvironmentMetrics {
  revenue: number;          // ← drift vs payload's revenue_current
  baseline_revenue: number; // ← drift vs payload's revenue_baseline
  delta_absolute: number;   // ← drift vs payload's delta_abs
  delta_percent: number;    // ← drift vs payload's delta_pct
  bacino: number;           // ← drift vs payload's bacino_current
  coverage: number;         // ← drift vs payload's coverage_current
}
```

**Result on every alert:** `m.bacino` and `m.coverage` are `undefined`. The `?? 0` fallback substitutes 0. Reduce-sum across 3 envs → `0 + 0 + 0 = 0`. Both "current" rows render as "0" / "0.0%". The baseline column DOES render real values (because `alert.baseline_bacino` and `alert.baseline_coverage` are top-level server-computed fields that DO match the contract).

**Marco sees:** `Bacino current = 0`, `Bacino baseline = 42,818`, `Coverage current = 0.0%`, `Coverage baseline = 82.18%`. Across all 238 alerts uniformly.

## Why hypothesis (i) was wrong

The plan's leading hypothesis assumed Phase 09 backfill alerts had empty `environment_split`. The Phase 11 SUMMARY and the environment_splitter run history say otherwise — every alert that flowed through the pipeline received an env_split. The bug is at the consumer (frontend), not at the producer (backend).

## Recommended fix scope (chosen path: PATH C — corrected from plan's binary A/B)

**Path C (root-cause fix, frontend-only, minimal blast radius):**

1. **Primary fix:** in `TriageSection.tsx`, read `m.bacino_current` and `m.coverage_current` (the actual payload field names). Keep `?? 0` as defense-in-depth for genuinely missing per-env values.
2. **Defensive Path B leftover:** still introduce `envSplitMissing` predicate + 'n/a' substitution + disclosure copy. This protects against the truly-empty-env_split edge case (legacy pre-Phase-11 alerts surfaced via `?include_deprecated=true`, or future env_splitter run failures that emit `{}`).
3. **Type fix optional / deferred:** `EnvironmentMetrics` interface drift in `frontend/src/types/alert.ts` affects `EnvironmentSplitSection.tsx` (Tab 5) and `EnvironmentBarChart` too. Those reads ALSO produce `undefined → fallback`. Out of scope for HOTFIX-05 (which targets Tab 2 Triage only) — but flagged as Phase 17.3 candidate (or sibling HOTFIX-08 if surfaced separately).

**Why not Path A (backend `current_bacino`/`current_coverage` top-level fields):** unnecessary — the data is already in env_split per-env, just under the right name. Adding a redundant top-level field would mask the contract-drift bug rather than fix it. Snapshot re-export not needed.

**Why not pure Path B (n/a substitution for empty env_split):** would leave Marco's actual issue unaddressed. 0% of his observed alerts have empty env_split. The "n/a" disclosure would never fire on the real data; he would still see "0".

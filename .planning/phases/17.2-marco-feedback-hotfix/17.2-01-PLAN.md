From frontend/src/components/charts/RevenueTrendChart.tsx lines 64-71 (the bug):
```tsx
<Tooltip
  formatter={(value, name) => [
    formatCurrency(Number(value)),
    name === 'revenue' ? 'Current Revenue' : 'Baseline',
  ]}
  labelStyle={{ fontWeight: 600, marginBottom: 4 }}
  contentStyle={TOOLTIP_STYLE}
/>
```

From the same file lines 73-91 (the two `<Line>` declarations whose `name` prop drives what recharts passes to the formatter's `name` argument):
```tsx
<Line
  type="monotone"
  dataKey="baseline"
  name="Baseline"           // ← recharts passes this string to formatter's `name`
  ...
/>
<Line
  type="monotone"
  dataKey="revenue"
  name="Current Revenue"    // ← recharts passes this string to formatter's `name`
  ...
/>
```

**Root cause:** `name === 'revenue'` is comparing the human label `"Current Revenue"` (or `"Baseline"`) against the dataKey string `"revenue"`. Always false → formatter returns `'Baseline'` for EVERY row.

**recharts API note (verified — recharts ≥2.x):**
The Tooltip `formatter` callback signature is `(value, name, item, index, payload)` where:
- `value` = the numeric data value
- `name` = the `<Line name="...">` prop string (display name)
- `item` = the recharts series object with `dataKey`, `stroke`, etc.

Two safe fixes:
1. Switch to `dataKey` discriminant via the 3rd argument: `(value, name, item) => [formatCurrency(...), item?.dataKey === 'revenue' ? 'Current Revenue' : 'Baseline']`
2. Switch the compare-target on the existing `name`: `name === 'Current Revenue' ? 'Current Revenue' : 'Baseline'` (idempotent — the formatter just echoes back the `<Line name>` prop, with the formatted value).

Option 1 is more robust (decouples display label from the discriminant). Option 2 is simpler. **Pick Option 1.**

The `RevenueStatusSection.tsx` (parent) embeds `<RevenueTrendChart data={trendData} />` — this chart's tooltip is the one Marco hovered (Step 1 "Revenue Impact" section).

## Decisions Made

- **Path A (label fix) over Path B (data reshape):** Per `17.2-CONTEXT.md` "Decisioni operatore" section, the operator pre-decided this trade-off at planning time. Path A is a 1-line literal swap with zero backend impact; Path B would require:
  - Backend change to `/api/alerts/{id}/trend` to produce 7-week rolling aggregates,
  - Contract review for any consumers of the `MetricDataPoint[]` shape,
  - JSON snapshot regen + Vercel re-deploy,
  - Bigger blast radius for a chart whose analytical value is debatable (daily granularity is arguably more useful for spotting day-level revenue dips than weekly rolling).
  Path A ships the truthfulness fix today; Path B can be revisited if a future operator argues weekly aggregation is genuinely more analytically valuable.
- **Intent comment retained inline (not extracted to i18n-keys.ts):** Per the plan's `<interfaces>` block, the surrounding pattern in `RevenueStatusSection.tsx` is JSX literals throughout — adding an i18n constant for one string would create inconsistency without benefit. A future Phase 18+ i18n sweep can refactor sibling literals together.
